
## CI build cache (ccache + restore/save pair), 18/11/2026

Branch `agent/android-arm64-application-port`. The Android CI had no compiler
cache: the ~1.6M-LOC engine recompiled every TU every run. SDK/NDK, the
`$RUNNER_TEMP/zhr-vendor` downloads and the Gradle home were already cached;
the gap was category "compiler output".

- `scripts/build/android/build-android.sh` now launcher-wraps CMake with ccache
  when present (`CMAKE_<LANG>_COMPILER_LAUNCHER`), optional (a machine without
  ccache is unchanged). `CCACHE_DIR=/home/runner/.ccache`, `CCACHE_BASEDIR=/home/runner`.
- Both workflows restore/save it. First commit `43c4319` used plain
  `actions/cache`; the follow-up `80fb8d5` switched to `actions/cache/restore`
  + `actions/cache/save` (both `@55cc8345…` = v6.1.0; the sub-actions resolve).
- **Plain `actions/cache` only saves on job success.** An app run cancelled at
  ~97% of the engine (`[1576/1631]`) saved nothing ("Post Restore the ccache
  compiler cache: skipped"). The explicit `save` with `if: always()` fixes it.
- Key: `android-ccache-<os>-<arch>-ndk<NDK_VERSION>-<ABI>-<build type>-<hash of
  build-android.sh + android.toolchain.cmake>-<run_id>-<run_attempt>`; three
  prefix `restore-keys`. No source hash (ccache is a content match).
  `ccache --set-config=compiler_check=content` for cross-compile hit reliability.
- Measured: cold test run 22m42s (1/1384 hits); warm test run **4m06s**
  (1382/1384 = 99.86%) — proven at commit `43c4319`. App run `44366426888`
  (commit `68a15c6`) is the first app **success** on this branch and proved the
  save step fires (`Cache saved with key: …-44366426888-1`). Next app run
  `44372296090` restored that key, hit **1374/1376 (99.85%)**, built the native
  engine in **2m48s** vs 21m37s cold, whole run **7m32s** vs 27m20s cold.
- Gotcha: a key saved under an OLD format with no trailing `-<run_id>` does NOT
  match a new `…-` restore-key, so the first run after a key-format change
  restores nothing (one extra cold build).
- `ci-android-app.yml` has `concurrency: cancel-in-progress: true` on
  `ci-android-app-${{ github.ref }}`: a newer push to the branch CANCELS an
  in-flight app run. Two "mysterious" cancellations were just this — don't push
  while an app run is mid-native-build if you want it to finish.
- Reference analysed: `redaF12-Tech/GeneralsZH-Android-Port` `main`
  `.github/workflows/build-android.yml` (vcpkg/DXVK/meson — none apply here;
  only the ccache design and the restore/save discipline carried over).
