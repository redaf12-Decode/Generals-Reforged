## Versions chosen (and why)
- Kotlin **2.2.0** — first KGP whose Gradle plugin officially supports **AGP 8.7.3**
  (2.1.20/2.1.21 stop at 8.7.2). Gradle 8.12 is inside KGP 2.2.0's range too.
- Compose compiler: **not a dependency** from Kotlin 2.0 on. It ships as the
  `org.jetbrains.kotlin.plugin.compose` Gradle plugin and must equal the Kotlin version.
  `composeOptions.kotlinCompilerExtensionVersion` no longer exists.
- Compose BOM **2025.06.01** → material3 **1.3.2**, ui/foundation/runtime **1.8.3**.
- `androidx.activity:activity-compose:1.10.1` (pulls activity 1.10.1).
- AGP 8.7.3 / Gradle 8.12 / compile+target 35 / min 28 / NDK 27.2.12479018 untouched.

## Two CI invariants that Compose silently breaks (both fixed, not relaxed)
- **Permission count.** `ci-android-app.yml` asserts `grep -c 'uses-permission'` on the
  *merged* manifest is **<= 2**. `androidx.core:core:1.13.1` (pulled by Compose) declares
  BOTH `<permission>` and `<uses-permission>` for
  `${applicationId}.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`. Removed both with
  `tools:node="remove"` markers in the main manifest. Safe because `${applicationId}` is
  resolved before merging (`ManifestHelper.setInjectableValues` → `setOverride(PACKAGE)`),
  so names match; and nothing registers a not-exported runtime receiver, which is the only
  caller of `ContextCompat.registerReceiver`'s guarded path.
- **APK lib set.** Same workflow fails on any `lib/` entry other than
  `lib/arm64-v8a/{libmain,libc++_shared}.so`. `androidx.graphics:graphics-path:1.0.1`
  (runtime dep of ui-graphics 1.8.3) ships `jni/*/libandroidx.graphics.path.so`.
  Excluded via `packaging { jniLibs { excludes.add '**/libandroidx.graphics.path.so' } }`
  (`JniLibsPackaging.getExcludes()` returns a mutable `Set<String>`, verified with javap).
  Only reached by Compose's `Path.iterator()`; this app iterates no Path.
- Also re-verified: no dependency AAR carries `assets/` (CI asserts none) and
  `ui-tooling` 1.8.3 has no assets/jni/permissions. App has no `src/*/assets` dir.

## Kotlin<->Java semantics verified empirically (kotlinc 2.2.0 + javac 17)
- An exhaustive `when` over a **Java** enum needs **no `else`** (Kotlin 2.x; adding one is
  only a "redundant else" warning). So `when (report.result)` over the 4 `Result` constants
  compiles without `else`.
- **Package-private Java constructors are callable from Kotlin in the same package**
  (`CompatibilityEvaluator.Check(...)` has a package-private ctor and works from
  `CompatibilityPresentationTest`, which lives in the same package).

## Integration shape
`SetupActivity`/`CompatibilityActivity` now `extends ComponentActivity` and hand their content
to Compose; ALL backend logic (picker, SAF grant, staging thread, `GameFolderStore`,
`GameFolderValidator`, launch) stayed in Java and was only re-expressed as state + `publish()`.
`LauncherHost.Callbacks` is the seam. Screens are stateless; `CompatibilityPresentation`
holds the display rules so they are host-testable.

## CI trigger gotcha (re-confirmed)
`ci-android-app.yml` runs on PR **paths** `android/**` (so this branch's PR does build+test the
APK), and on push only to `agent/android-arm64-application-port`. `ci-android-test.yml` push
trigger is `android-arm64-port`; it has no `android/**` path filter, so it does NOT fire here.
`linux-release.yml` has an unfiltered `pull_request:` trigger — it will run on any PR, but it is
the workflow already failing at `GeneralsMD/Code/Tests/test_vendor_no_art.sh` (missing
`*.patch` in its fixture), which is pre-existing and unrelated to this change.
